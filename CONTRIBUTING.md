# Contributing

Contributions are welcome.

Good contributions include:

- new tool-specific instruction files
- measured before/after examples
- prompt templates
- workflow patterns
- context hygiene techniques
- model routing examples
- agent memory compression tips

## Style

- Keep content practical.
- Avoid exaggerated token-saving claims.
- Prefer examples over theory.
- Do not copy proprietary tool prompts or private company instructions.
- Do not sacrifice accuracy for extreme brevity.

## Learning From External Projects

This repository deliberately learns from useful public repositories, standards, papers, and tools. When a contribution is materially inspired by an external source, follow the [external pattern intake and provenance process](docs/external-pattern-intake.md).

In particular:

- record the source, revision or review date, and licence;
- explain the local problem the pattern solves;
- separate the reusable principle from source-specific implementation details;
- preserve required attribution or notices when material is reused;
- independently validate quantitative claims instead of repeating upstream marketing numbers;
- add the synthesized rule to one canonical local document and link to it rather than duplicating guidance.

If reuse terms are unclear, prefer an original vendor-neutral summary of the idea or do not reuse the material.

## Pull Request Checklist

- [ ] The contribution is practical.
- [ ] The wording is concise.
- [ ] No confidential content is included.
- [ ] Any claims are realistic or clearly marked as examples.
- [ ] Material external sources are identified with a stable URL and revision/review date where possible.
- [ ] Licence and attribution obligations were checked for any reused text, code, data, or examples.
- [ ] Quantitative claims were independently measured or clearly labelled as unverified source claims.
- [ ] New guidance has one canonical home and does not duplicate existing rules unnecessarily.
